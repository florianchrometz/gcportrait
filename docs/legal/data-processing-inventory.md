# Data-processing inventory: gcportrait.app and demo.gcportrait.app

**A fact sheet, not legal advice; not yet reviewed by a lawyer.**

Every processing of personal data by the two sites the maintainer hosts (ADR 0032; ADR 0035 §2): the website
`gcportrait.app` (static pages on GitHub Pages) and the demo `demo.gcportrait.app` (the image in demo-only
mode on Cloud Run, region `europe-west1`). The privacy notice, on the maintainer's website at
<https://florian-chrometz.de/legal/privacy-policy> and linked from both sites ([README](README.md)), describes each row in
plain words: what it says about the website is rows W1 to W4, about the demo's logs and overload counter rows R1
to R3, about the demo's storage in the browser row R4, and about email row C1. The controller is the person named in
the Impressum, <https://florian-chrometz.de/legal/impressum>. Self-hosted instances of gcportrait are not covered:
whoever runs one is its operator ([self-host-options.md](../self-host-options.md#legal-pages-link-or-serve)).

## Not processed

Each item was checked on 2026-10-11 and is part of what the notice promises. A change to any of them needs a
new row above and a new privacy notice.

- **No cookies by the website, and no storage but rows W2 to W4**: the only client code that keeps anything is the
  documentation pages' fillable commands (row W2), the header's repository widget (row W3, session storage) and the
  page views' random identifiers (row W4, session storage); the
  demo videos' player (`website/src/components/DemoVideo.astro`) and the menu buttons keep nothing. The demo's
  server sets no cookie.
- **No analytics but the website's page views (row W4), no telemetry in the app or the demo, no tracking across
  sites, advertising or social-media plug-ins, and no request to other hosts but rows W3 and W4**: `pnpm
  website:check` fails a page that loads anything from another host, or whose scripts ask any other host than
  `api.github.com` for the repository widget (row W3) and TelemetryDeck's ingestion host for the page views (row W4),
  and fails a demo that names TelemetryDeck; the demo's Content Security Policy allows only its own host (and
  `data:` images), and its app has no telemetry.
- **No sign-in and no Google Cloud data in the demo**: with `DEMO_ONLY=true` the backend refuses an OAuth
  client and service-account mode and does not register the routes that call Google (ADR 0032,
  `backend/src/demo-only.test.ts`).
- **No server-side storage**: the backend has no database and no bucket ([ADR 0005](../adr/0005-stateless-backend-browser-snapshots.md)); the part of an address
  after `#`, where the app keeps its view, never reaches the server.
- **No transfer by the maintainer** to anyone but the providers in the table.

## When to update

When the website or the demo change host, region, log settings or retention; when the code adds a request to
another host, a cookie, a storage key, a logged header or a form; when a third hosted surface appears. Then
update this table, the privacy notice on the maintainer's website and, for a new provider, the scope of the
Impressum there ([README](README.md)).
